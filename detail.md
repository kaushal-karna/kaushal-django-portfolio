# Complete Project Guide

This guide explains the portfolio from the beginning. It is written for someone who is learning Django and wants to install, run, customize, test, and prepare the project for deployment.

**Documentation navigation:** [Project overview](README.md) · [Command reference](command.md) · [Environment template](.env.example)

## 1. What This Project Is

This is a personal portfolio website built with Django. It has a public homepage, project detail pages, an admin area, a contact form, and automatic thank-you emails.

The visitor can:

- Read the introduction, education, skills, and learning journey.
- Filter projects by category.
- Open a project case-study page.
- Switch between dark and light themes.
- Send a message through the contact form.
- Receive a thank-you email after sending a valid message.

The owner can:

- Add and edit projects in Django admin.
- Add and edit skills in Django admin.
- Read contact messages in Django admin.
- Update the visual design in CSS and JavaScript.

## 2. How Django Fits Together

Django separates the application into clear responsibilities:

- `config/settings.py` contains project configuration and environment variables.
- `config/urls.py` connects the main URL configuration to the portfolio app.
- `portfolio/urls.py` maps homepage, contact, and project detail URLs.
- `portfolio/views.py` decides what each page and form submission does.
- `portfolio/models.py` defines database tables.
- `portfolio/forms.py` validates contact form input.
- `templates/` contains HTML generated by Django.
- `static/` contains CSS and browser JavaScript.
- `manage.py` runs Django commands.

The main request flow looks like this:

```text
Browser -> URL -> View -> Model/Form -> Template -> Browser
                         |
                         -> Email service for contact confirmations
```

## 4. Install on Windows

Open PowerShell in the folder that contains `manage.py`.

### Create and activate a virtual environment

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

If PowerShell blocks activation for the current terminal, run this first:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

### Install packages

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### Prepare the database

```powershell
python manage.py migrate
python manage.py seed_portfolio
```

### Create an admin account

```powershell
python manage.py createsuperuser
```

Enter a username, email address, and password when prompted.

### Start the website

```powershell
python manage.py runserver
```

Visit:

- Website: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)
- Admin: [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/)

## 5. Install on Linux or macOS

python3 -m venv venv

## 6. Configure Environment Variables

Django loads `.env` from the project root through `python-dotenv`.

Create your local environment file from the safe template:

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Linux or macOS:

```bash
cp .env.example .env
```

Never commit `.env`. It is ignored by `.gitignore`.

### Important variables

| Variable | Purpose |
| --- | --- |
| `SECRET_KEY` | Signs sessions, CSRF tokens, and other Django data |
| `DEBUG` | Shows detailed errors during development; use `False` in production |
| `ALLOWED_HOSTS` | Comma-separated hostnames accepted by Django |
| `SITE_URL` | Website link included in confirmation emails |
| `DEFAULT_FROM_EMAIL` | Sender shown on outgoing emails |
| `EMAIL_BACKEND` | Console backend locally or SMTP backend for real delivery |
| `EMAIL_HOST` | SMTP provider hostname |
| `EMAIL_PORT` | SMTP provider port, usually `587` for TLS |
| `EMAIL_HOST_USER` | SMTP username, often your email address |
| `EMAIL_HOST_PASSWORD` | SMTP password or provider app password |
| `EMAIL_USE_TLS` | Enables STARTTLS, normally used with port `587` |
| `EMAIL_USE_SSL` | Enables implicit SSL, normally used with port `465` |
| `CONTACT_RECEIVER_EMAIL` | Gmail address that receives new portfolio messages |

## 7. Test Email Locally First

The default local backend is:

```text
EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
```

With this backend, the email is generated correctly but printed in the terminal. It is not sent to a real inbox. This is the safest way to test the contact form first.

1. Start the server with `python manage.py runserver`.
2. Open the homepage.
3. Scroll to the contact section.
4. Fill in your name, email, subject, and message.
5. Submit the form.
6. Look at the terminal running Django.
7. You should see the plain-text email and the HTML alternative.

The message is saved to the database even when email delivery fails.

## 8. Configure Real Email Sending

For real delivery, change the email values in `.env`.

### Gmail example

Gmail normally requires an App Password for SMTP access. Do not use your normal Google account password.

1. Enable two-step verification on the Google account.
2. Create a Google App Password.
3. Copy the generated app password.
4. Put it in `.env` as `EMAIL_HOST_PASSWORD`.

Example:

```text
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_HOST_USER=your-email@gmail.com
EMAIL_HOST_PASSWORD=your-16-character-app-password
EMAIL_USE_TLS=True
EMAIL_USE_SSL=False
DEFAULT_FROM_EMAIL=Kaushal Karn <your-email@gmail.com>
CONTACT_RECEIVER_EMAIL=your-email@gmail.com
SITE_URL=https://your-domain.example
```

Restart Django after changing `.env`. Environment variables are loaded when the process starts.

### Other email providers

Use the SMTP host, port, encryption mode, username, and password supplied by your provider. Common patterns are:

- Port `587` with `EMAIL_USE_TLS=True` and `EMAIL_USE_SSL=False`.
- Port `465` with `EMAIL_USE_TLS=False` and `EMAIL_USE_SSL=True`.

Do not enable both TLS and SSL unless your provider specifically requires it.

## 9. How the Contact Email Works

The contact endpoint is `/contact/` and accepts a POST request from the form.

1. Django validates the submitted fields with `ContactForm`.
2. A `ContactMessage` record is saved in the database.
3. Django renders a plain-text email from `templates/emails/contact_thank_you.txt`.
4. Django renders a styled HTML email from `templates/emails/contact_thank_you.html`.
5. Django sends both versions to the visitor's submitted email address.
6. Django sends a separate notification containing the full message to `CONTACT_RECEIVER_EMAIL`.
7. The visitor sees a success message on the portfolio.

If the SMTP provider is unavailable, the database message is still kept and the visitor sees a warning instead of a false success message.

## 13. Run with Gunicorn or Daphne

Do not use `runserver` as a production server.

### Gunicorn WSGI server

Gunicorn is commonly used on Linux servers:

```bash
gunicorn config.wsgi:application
```

To bind to a port:

```bash
gunicorn config.wsgi:application --bind 0.0.0.0:8000
```

### Daphne ASGI server

Daphne is useful when deploying Django through an ASGI stack:

```bash
daphne config.asgi:application
```

To bind to a port:

```bash
daphne -b 0.0.0.0 -p 8000 config.asgi:application
```

Use the server style supported by your hosting provider. You normally choose Gunicorn or Daphne, not both for the same web process.

## 14. Production Checklist

Before deploying:

- Set `DEBUG=False`.
- Generate a unique production `SECRET_KEY`.
- Set `ALLOWED_HOSTS` to the real domain names.
- Set `SITE_URL` to the public HTTPS URL.
- Configure a real SMTP backend and verify it with a test email.
- Use a production database when the hosting platform requires one.
- Run `python manage.py migrate`.
- Run `python manage.py collectstatic --noinput`.
- Serve `staticfiles/` through the hosting platform or web server.
- Configure HTTPS, secure cookies, and trusted origins.
- Run `python manage.py check --deploy`.
- Add automated tests for the contact form and email flow.

## 15. Troubleshooting

### `python` is not recognized

Install Python, restart the terminal, and confirm it with:

```powershell
python --version
```

### PowerShell refuses to activate the environment

Run this only in the current PowerShell process:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Then activate `venv` again.

### The website starts but CSS is missing

Run:

```powershell
python manage.py collectstatic --noinput
```

For development, confirm that `static/` exists and that `django.contrib.staticfiles` is installed.

### The email appears in the terminal

That is expected when `EMAIL_BACKEND` is set to the console backend. Use SMTP settings from the email provider when real delivery is needed.

### The email is not delivered

Check the SMTP host, port, username, password, TLS/SSL combination, sender address, and provider restrictions. Restart Django after editing `.env`. Read the terminal log for the exact SMTP error.

### The contact message is saved but email fails

This is intentional. The app keeps the visitor's message and displays a warning so no contact request is lost. Fix SMTP configuration and send a test message again.

### `DisallowedHost` appears

Add the hostname to `ALLOWED_HOSTS` in `.env`, for example:

```text
ALLOWED_HOSTS=127.0.0.1,localhost,your-domain.example
```
